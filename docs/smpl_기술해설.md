# 1장. SMPL이란 무엇인가

## 1.1 풀어야 할 문제

영상에서 사람의 3D 몸을 복원한다고 하자. 결과물은 **3D 메쉬**(삼각형으로 이루어진 껍데기)여야 한다.

메쉬를 신경망이 직접 예측하게 하면 어떻게 될까. SMPL 메쉬는 정점이 6,890개이고
각 정점은 (x, y, z) 좌표를 가지므로 **20,670개의 숫자**를 맞혀야 한다.

문제는 정확도가 아니라 **구조**다. 신경망이 20,670개 숫자를 자유롭게 뱉으면
팔이 세 개인 형체, 몸통에 구멍이 뚫린 형체, 무릎이 반대로 꺾인 형체가 나온다.
신경망은 "사람은 팔이 둘"이라는 사실을 모르기 때문이다.

## 1.2 SMPL의 관찰 — 인체는 저차원이다

[SMPL](https://dl.acm.org/doi/10.1145/2816795.2818013) (Loper et al., SIGGRAPH Asia 2015)이
발견한 것은 이렇다. 수천 명의 3D 스캔을 같은 토폴로지로 정렬해 놓고 보면,
사람 몸의 모든 변화가 **80여 개의 숫자로 표현된다.**

```
β (베타) — 체형, 10개
   "키가 크고 마른 편이다" 같은 정보. 같은 사람이면 시간이 지나도 변하지 않는다.

θ (세타) — 포즈, 72개  =  관절 24개 × 회전 3개(축-각)
   "오른쪽 팔꿈치가 90도 굽었다" 같은 정보. 프레임마다 바뀐다.
```

그래서 SMPL은 **함수**다.

```
      SMPL(β, θ)  →  정점 6,890개의 3D 좌표
    ─────────────     ────────────────────────
      82개 숫자          20,670개 숫자
```

원논문의 표기로는 이렇다.

```
M(β, θ) = W( T(β, θ), J(β), θ, W )
T(β, θ) = T̄ + B_S(β) + B_P(θ)
```

- `T̄` — 평균 인체 템플릿 (상수)
- `B_S(β)` — 체형 블렌드셰이프
- `B_P(θ)` — 포즈 블렌드셰이프
- `J(β)` — 체형에 따라 결정되는 관절 위치
- `W` — 선형 블렌드 스키닝(LBS)

원논문은 아티스트가 만든 정점 6,890개, 관절 23개(+루트 = 24)의 메쉬에서
출발한다고 명시한다. 남녀 동일 토폴로지이며 사분면(quad) 구조와
부위 분할, 초기 블렌드 가중치, 골격 리그를 갖는다.

## 1.3 내부에서 일어나는 일 — 네 단계

```
① 평균 체형 템플릿  T̄
   전 인류의 평균 몸. 고정된 6,890개 정점. 상수다.

        ┌──┐
        │  │
       ─┼──┼─
        │  │
       ╱    ╲

② + 체형 블렌드셰이프  B_S(β)
   β 를 넣으면 키를 늘리고 어깨를 넓히고 배를 넣는다.
   정점들이 β 에 비례해 움직인다. 아직 T-포즈로 서 있다.

        ┌───┐
        │   │
       ─┼───┼─
        │   │
       ╱     ╲

③ + 포즈 블렌드셰이프  B_P(θ)
   ★ SMPL 의 핵심 기여
   "팔을 굽히면 이두박근이 튀어나온다" 같은 포즈에 따른 연부조직 변형을
   미리 학습해 둔다. 원논문은 이것을 회전행렬 원소의 선형 함수로 정의해
   서로 다른 사람·자세의 정렬된 3D 메쉬로부터 모델 전체를 학습할 수 있게 했다.

       ╭──╮
       │▓▓│   ← 팔을 굽히니 이두가 볼록해진다

④ LBS 스키닝
   뼈대 24개를 θ 대로 회전시키고, 각 피부 정점이 어느 뼈를 얼마나 따라갈지
   가중치대로 이동시킨다.

       \  o  /
        \/|\/
          |
         / \
```

②까지가 "누구인가", ③④가 "어떤 자세인가"다.

**③이 왜 중요한가.** LBS만 쓰면 관절이 접히는 곳에서 부피가 사라진다.
팔꿈치를 굽히면 살이 종잇장처럼 눌리는 이른바 "캔디 래퍼" 현상이 나타난다.
포즈 블렌드셰이프는 그 변형을 데이터로부터 학습해 보정한다. SMPL이
그 이전 모델들보다 자연스러운 이유가 여기에 있다.

## 1.4 β를 자세히

### 어디서 나온 숫자인가

```
① 사람 수천 명을 3D 스캔한다.
   스캔마다 정점 개수도 구조도 제각각이다.

② 레지스트레이션 — 모든 스캔을 SMPL 토폴로지로 맞춘다.
   이제 모두가 정확히 6,890개 정점을 갖고,
   "3891번 정점 = 코끝"이 모든 사람에게 동일하게 성립한다.

③ 사람 한 명 = 숫자 20,670개 = 20,670차원 공간의 점 하나

④ 4천 명 = 그 공간의 점 4천 개
```

**"20,670차원 공간의 점"은 겁먹을 표현이 아니다.** 차원이란 숫자의 개수를 말한다.
키만 재면 1차원(직선 위의 점), 키와 몸무게를 재면 2차원(산점도의 점),
셋이면 3차원이다. 20,670개면 20,670차원이고, 그릴 수 없을 뿐 거리·평균·방향
같은 계산은 2차원 산점도에서 하던 것과 똑같이 작동한다.

**레지스트레이션이 없으면 이 모든 것이 불가능하다.** 스캐너 원본은 사람마다
정점 수도 순서도 다르므로 "3891번째 숫자끼리 비교"가 아무 의미가 없다.
모두에게 같은 20,670칸짜리 양식을 채우게 만드는 작업이 레지스트레이션이다.

### PCA — 인체가 놓인 얇은 판을 찾는다

20,670차원 공간은 상상하기 어려울 만큼 넓다. 아무 숫자나 20,670개 넣으면
사람 모양은커녕 무작위 먼지구름이 나온다. 그런데 실제 사람 4천 명의 점은
그 광활한 공간의 아주 좁은 구석에만 몰려 있다. 팔이 몸통에 붙어 있고,
머리가 위에 있고, 좌우가 대칭이라는 제약이 어마어마하게 많기 때문이다.

```
3차원 방 안에 종이 한 장이 비스듬히 떠 있다고 하자.

        ╱▔▔▔▔▔▔▔╱
       ╱  ·  ·  ╱
      ╱ ·  · ·╱
     ╱▁▁▁▁▁▁╱

  종이 위의 점을 표현하는 데 몇 개 숫자가 필요할까?
    방 기준으로는   (x, y, z)      3개
    종이 기준으로는 (가로, 세로)   2개면 충분하다
```

인체도 같다. 20,670차원 공간 안에 "가능한 인체"라는 얇은 판이 떠 있고,
그 판 자체는 10차원 정도면 충분하다. **그 판 위의 좌표가 β 다.**

수식으로는 이렇다.

```
T(β) = T̄ + β₁·S₁ + β₂·S₂ + … + β₁₀·S₁₀
```

`Sₙ` 은 n번 축 방향으로 6,890개 정점이 어떻게 움직이는지를 담은
(6890 × 3) 크기의 변위 벡터장이며, 모델 파일에 저장되어 있다.

### 각 β가 무엇을 뜻하는가 — 정직하게

```
β₁  ≈  전체 크기 / 키          ← 경험적으로 대략 그렇게 보인다
β₂  ≈  체중 / 마름-뚱뚱         ← 대략
β₃~ ≈  여러 요소가 뒤섞여 사람이 이름 붙일 수 없다
```

이것은 공식 정의가 아니다. PCA는 "분산이 큰 방향"을 수학적으로 찾을 뿐,
그것이 인간이 이해하는 개념(키, 체중, 어깨너비)과 일치할 이유가 없다.
1~2번은 우연히 해석되지만 3번부터는 뒤섞인다.
[Anny](https://europe.naverlabs.com/blog/anny-a-free-to-use-3d-human-parametric-model-for-all-ages/)가
해석 가능한 슬라이더를 내세우는 이유가 정확히 이 지점이다 (2장 참조).

### 왜 10개인가

[SMPL 1.1.0](https://smpl.is.tue.mpg.de/) 은 300개까지 제공한다. 그런데
실무에서는 거의 항상 10개만 쓴다.

```
설명되는 분산
   100%│                    ╭──────────────
       │              ╭─────╯
       │        ╭─────╯
       │    ╭───╯
       │  ╭─╯
       │ ╱
     0 └────┬──────────────────────────────
          10개                          300개
```

10개면 키·체중·허리둘레·어깨너비 같은 몸 실루엣의 대부분을 잡는다.
11번 이후는 보조개나 살주름 같은 미세 굴곡이라, 영상에서 추정하는
HMR 과제에는 오히려 방해가 된다. 관측할 수 없는 것을 추정하려다
과적합하기 때문이다.

### β는 신원이다 — 우리 평가의 무기

β는 시간에 불변이어야 한다. 그래서 이렇게 쓸 수 있다.

```
track_id = 0 인 선수의 β₁

프레임    0    1    2  …  1450  1451  1452 …
β₁     0.31 0.30 0.32 …  0.29  -1.87 -1.90 …
                                ▲
                                여기서 β 가 급변
                                → ID 스왑 의심
```

**정답 데이터 없이 오류를 탐지할 수 있다.** 본 프로젝트의 `metrics/plausibility.py`가
이 원리를 구현한 것이며, β를 쓸 수 없는 경우(Anny→SMPL 변환 실패 등)에는
뼈 길이의 변동계수가 같은 역할을 대신한다. β가 체형을 결정하고 체형이
뼈 길이를 결정하므로 둘은 같은 것을 재기 때문이다.

## 1.5 θ를 자세히

### 24 × 3 = 72

관절 j 의 회전은 `θ[3j : 3j+3]` 에 들어 있다.

| idx | 관절 | θ 인덱스 | idx | 관절 | θ 인덱스 |
|---|---|---|---|---|---|
| 0 | pelvis (루트) | `θ[0:3]` | 12 | neck | `θ[36:39]` |
| 1 | left_hip | `θ[3:6]` | 13 | left_collar | `θ[39:42]` |
| 2 | right_hip | `θ[6:9]` | 14 | right_collar | `θ[42:45]` |
| 3 | spine1 | `θ[9:12]` | 15 | head | `θ[45:48]` |
| 4 | left_knee | `θ[12:15]` | 16 | left_shoulder | `θ[48:51]` |
| 5 | right_knee | `θ[15:18]` | 17 | right_shoulder | `θ[51:54]` |
| 6 | spine2 | `θ[18:21]` | 18 | left_elbow | `θ[54:57]` |
| 7 | left_ankle | `θ[21:24]` | 19 | right_elbow | `θ[57:60]` |
| 8 | right_ankle | `θ[24:27]` | 20 | left_wrist | `θ[60:63]` |
| 9 | spine3 | `θ[27:30]` | 21 | right_wrist | `θ[63:66]` |
| 10 | left_foot | `θ[30:33]` | 22 | left_hand | `θ[66:69]` |
| 11 | right_foot | `θ[33:36]` | 23 | right_hand | `θ[69:72]` |

22·23번 `left_hand`/`right_hand` 는 **손목 아래 통짜 덩어리 하나**다.
손가락이 없다. 이것이 SMPL-X가 필요해지는 이유다 (2장).

### 축-각 표현

각 관절의 3개 숫자는 오일러각이 아니라 **축-각(axis-angle)** 이다.

```
r = [rx, ry, rz]  이 3차원 벡터가 통째로 하나의 회전을 뜻한다

   방향 (r / ‖r‖)  =  회전축
   길이 (‖r‖)      =  회전 각도 (라디안)

예시
   r = [0, 0, 0]        →  회전 없음
   r = [0, 0, 1.5708]   →  z축 중심 90도  (π/2)
   r = [3.1416, 0, 0]   →  x축 중심 180도
```

|  | 축-각 | 오일러각 | 회전행렬 | 쿼터니언 |
|---|---|---|---|---|
| 숫자 개수 | **3** | 3 | 9 | 4 |
| 제약 조건 | **없음** | 없음 | 직교·det=1 | 단위길이 |
| 짐벌락 | 없음 | **있음** | 없음 | 없음 |

"제약 없음"이 핵심이다. 신경망이 아무 3개 숫자나 뱉어도 항상 유효한 회전이 된다.
회전행렬을 예측시키면 9개 숫자가 직교행렬이 아닐 수 있어 후처리가 필요하다.

다만 축-각도 단점이 있다. `r` 과 `r + 2πk` 가 같은 회전이라 표현이 중복이고,
180도 근처에서 불연속이다. 그래서 최근 모델들은 내부적으로 6D 회전 표현을 쓰고
마지막에 축-각으로 변환해 내보낸다. 본 프로젝트에서 조사한
[Multi-HMR 2](https://arxiv.org/abs/2606.14841) 도 6D 회전을 출력한다.

### 회전은 부모 대비 상대다

가장 오해하기 쉬운 부분이다.

```
키네매틱 트리 (부모 → 자식)

  0 pelvis ─┬─ 1 L_hip ── 4 L_knee ── 7 L_ankle ── 10 L_foot
            ├─ 2 R_hip ── 5 R_knee ── 8 R_ankle ── 11 R_foot
            └─ 3 spine1 ─ 6 spine2 ─ 9 spine3 ─┬─ 12 neck ── 15 head
                                               ├─ 13 L_collar ─ 16 L_shoulder ─ 18 L_elbow ─ 20 L_wrist ─ 22 L_hand
                                               └─ 14 R_collar ─ 17 R_shoulder ─ 19 R_elbow ─ 21 R_wrist ─ 23 R_hand
```

`θ[57:60]`(오른 팔꿈치)은 "세상 기준 팔뚝 방향"이 아니라 "위팔 기준으로
얼마나 굽었는가"다.

```
상황 A: 팔을 앞으로 뻗고 팔꿈치 90도
상황 B: 팔을 위로 들고 팔꿈치 90도

  → 세상에서 손 위치는 완전히 다르다
  → 그런데 θ[57:60] 은 두 경우 똑같다 (둘 다 "90도 굽음")
  → 차이는 어깨 θ[51:54] 에 들어 있다
```

최종 3D 위치는 트리를 타고 내려가며 변환을 누적해 얻는다.

```
G_손목 = G_pelvis · G_spine1 · G_spine2 · G_spine3 · G_collar · G_shoulder · G_elbow · G_wrist
```

**실무적 함의**: 어깨 추정이 5도 틀리면 손목 위치는 크게 어긋난다.
오차가 트리 아래로 누적되기 때문이다. 관절 오차를 잴 때 골반 기준으로
정렬하거나(MPJPE) 전역 정렬을 하는(PA-MPJPE) 이유가 여기 있다.

### `θ[0:3]`은 특별하다

0번 pelvis 는 부모가 없다. 그래서 이것은 "몸 전체가 세상에서 어느 방향을
보고 있는가"이며 보통 `global_orient` 라고 따로 부른다.

```
θ (72)  =  global_orient (3)  +  body_pose (69)
```

## 1.6 파라메트릭 방식의 이점 다섯 가지

| | 왜 좋은가 |
|---|---|
| ① 항상 사람 모양 | β·θ에 어떤 값을 넣어도 사람이 나온다. 인체에 대한 사전지식이 모델 안에 박혀 있다 |
| ② 학습이 쉽다 | 신경망이 20,670개 대신 82개만 맞히면 된다 |
| ③ 압축 | 프레임당 82개면 충분하다 |
| ④ 의미가 읽힌다 | `θ[57:60]` = 오른 팔꿈치 회전. 직접 읽고 쓸 수 있다 |
| ⑤ 호환 | 같은 규격이면 다른 도구·데이터와 섞어 쓸 수 있다 |

### 실감나는 숫자

본 프로젝트 데이터셋의 테니스 클립 하나를 예로 든다.

```
cam1_2K.mp4 : 1920×1080, 2,309프레임, 인물 4명, 19 MB

    β     :  4명 × 10            =        40 개   ← 영상 전체에 이것뿐
    θ     :  4명 × 2,309 × 72    =   664,992 개
    transl:  4명 × 2,309 × 3     =    27,708 개
    ─────────────────────────────────────────────
    합계                          ≈  692,740 개
                                 float32 → 약 2.8 MB
```

19MB 영상에서 사람의 모든 움직임이 2.8MB로 남는다.
④의 "의미가 읽힌다"는 성질 덕분에 이 숫자들을 곧바로 동작 분석에 쓸 수 있다.
5장에서 다룰 VTG 활용의 출발점이다.

# 2장. 계보

## 2.1 바디 모델 — 몸의 규격

이 계층은 **영상을 보지 않는다.** 숫자를 넣으면 메쉬가 나오는 수학 함수일 뿐이다.

| 모델 | 발표 | 정점 | 손·얼굴 | 특징 | 라이선스 |
|---|---|---|---|---|---|
| **SMPL** | 2015 | 6,890 | ✗ | 사실상 표준. 10년치 생태계 | 등록·비상업 |
| **SMPL-X** | 2019 | 10,475 | ✓ MANO+FLAME | SMPL의 상위집합. 관절 약 54개 | 등록·비상업 |
| STAR | 2020 | 6,890 | ✗ | SMPL보다 작고 체형 정확도 개선 | 등록 |
| SUPR | 2022 | — | ✓ | 부위별 분리 가능 | 등록 |
| GHUM | Google | — | ✓ | 비선형 매핑으로 표현력 확대 | 제한적 |
| **Anny** | 2025 | 13,000+ | ✓ | 스캔 없이 인체계측+WHO 통계 | **Apache 2.0** |

### SMPL → SMPL-X

[SMPL-X](https://smpl-x.is.tue.mpg.de/) (Pavlakos et al., CVPR 2019)는
SMPL을 확장해 손(MANO)과 얼굴(FLAME)을 포함한다. 정점 10,475개, 관절 54개다.

```
SMPL    :  어깨 ─ 팔꿈치 ─ 손목 ─[손은 벽돌 하나]
SMPL-X  :  어깨 ─ 팔꿈치 ─ 손목 ─┬ 엄지(3관절)
                                 ├ 검지(3관절)
                                 ├ 중지(3관절)   ← 손가락 15관절 × 2손
                                 ├ 약지(3관절)
                                 └ 새끼(3관절)   + 턱·눈·표정
```

**SMPL-X는 SMPL의 상위집합이므로 선택 비용이 사실상 0이다.** 손·얼굴
파라미터가 필요 없으면 무시하면 SMPL과 같아진다.

다만 실전에서는 **손이 화면에서 몇 픽셀인가**가 관건이다. 원거리 샷에서
손이 10픽셀 수준이면 모델이 내놓는 손 파라미터는 관측이 아니라 사전분포가
만들어낸 값이다. 본 프로젝트가 `metrics/handsize.py` 로 데이터셋별 손
픽셀 크기를 실측한 뒤 SMPL-X 확장 여부를 결정하기로 한 이유다.

### Anny — 스캔 없는 대안

[Anny](https://arxiv.org/abs/2511.03589) (NAVER LABS Europe, 2025)는
SMPL 계열의 세 가지 문제를 겨냥한다.

```
문제 ① 스캔 의존   3D 스캐너가 비싸고 재현이 어렵다
문제 ② 인구 편향   스캔 대상이 대부분 건강한 성인이라
                   영유아·노인·비정형 체형이 데이터에 거의 없다
문제 ③ 프라이버시  3D 전신 스캔은 생체정보라 공유·재배포에 법적 제약이 있다
```

Anny는 스캔을 전혀 쓰지 않는다. 대신 오픈소스 3D 캐릭터 커뮤니티
**MakeHuman** 의 아티스트 자산, **인체계측학** 지식, **WHO 인구 통계**로
캘리브레이션한다. 정점 13,000개 이상, 뼈 163개, 아티스트 정의 블렌드셰이프 564개다.

가장 큰 차별점은 **파라미터가 해석 가능하다**는 것이다.

```
SMPL 의 β    = [0.31, -1.22, 0.84, …]   ← 각 축의 의미를 알 수 없다
Anny 의 파라미터 = 성별·나이·키·몸무게·근육 슬라이더  ← 사람이 직접 조작할 수 있다
```

논문의 핵심 주장은 "Anny로 학습한 HMR 모델이 스캔 기반 바디모델로 학습한
것과 대등한 성능을 낸다"는 것이다. 스캔의 비용·편향·프라이버시 문제를
성능 손실 없이 없앤 셈이다.

**호환성**: v0.3(2026-02)에서 `smplx` 토폴로지가 추가됐고 v0.6(2026-08)에는
`smpl`/`smplx`/`soma` 리토폴로지가 제공된다. 다만 리토폴로지는 **메쉬 정점을
SMPL 토폴로지로 옮기는 것**이지 SMPL의 θ/β 파라미터를 주는 것이 아니다.
파라미터가 필요하면 메쉬에 SMPL을 피팅하는 단계가 추가로 붙는다.

**라이선스 주의**: Anny 코드와 자체 자산은 Apache 2.0이지만,
`smplx` 토폴로지로 내보낸 결과물은 SMPL-X 규격을 쓰는 것이라
MPI의 비상업 라이선스가 따라붙는다. 연구 목적에는 무관하다.

**생태계는 아직 얇다.** SMPL은 10년치 평가 코드·데이터셋 GT·BVH 변환·
게임엔진 연동이 쌓여 있는 반면 Anny는 2025년에 등장했고 현재
Multi-HMR 2 외에 쓰는 곳이 거의 없다.

## 2.2 추정 기법 — 영상에서 숫자를 맞히기

이 계층이 신경망이다. 픽셀을 받아 1장의 β·θ를 출력한다.

### 최적화 → 회귀 → 하이브리드

```
SMPLify (2016)          최적화
  2D 키포인트를 검출하고 SMPL 파라미터를 반복적으로 조정해
  3D-2D 재투영 오차와 사전분포 항을 최소화한다.
  정확하지만 영상 한 장에 수십 초가 걸린다.
        │
        ▼
HMR (2018)              회귀
  CNN 이 SMPL 파라미터를 직접 예측한다. 최적화의 속도 문제를 없앴다.
  적대적 사전분포로 "사람다운 자세"를 강제한다.
        │
        ▼
SPIN (2019)             하이브리드
  회귀와 SMPLify 를 학습 루프 안에서 번갈아 돌린다.
  회귀 결과를 최적화가 다듬고, 그 결과를 다시 회귀의 지도신호로 쓴다.
```

|---|---|---|

| CLIFF | ECCV 2022 | 크롭이 아닌 전체 프레임 위치를 인지 |

### 비디오와 트래킹

정지 영상 한 장씩 처리하면 결과가 프레임마다 튄다. 시간 축을 다루는 계보가
따로 자란 이유다.

```
VIBE (2020)        비디오 시퀀스 + 적대적 모션 사전분포
      │
PHALP (CVPR 2022)  "3D 외모·위치·자세를 예측해 사람을 추적한다"
      │            탐지 후 매칭 방식의 대표
      │
4D-Humans (2023)   HMR 2.0 + PHALP. 트래킹 SMPL 의 사실상 표준
      │
      ├── 월드 좌표 계열 ────────────────────────────
      │   WHAM (CVPR 2024) — 카메라 모션을 결합
      │   TRAM (ECCV 2024) — SLAM + 비디오 트랜스포머, 다인물 지원
      │   GVHMR (SA 2024, TPAMI 2026) — 중력-뷰 좌표로 드리프트 억제
      │   OnlineHMR (CVPR 2026) — 인과적 스트리밍 추론
      │
      └── 다인물 동시 추적 계열 ──────────────────────
          CoMotion (ICLR 2025)     — 순환 상태로 갱신
          Multi-HMR 2 (2026)       — DETR 검출 + SAM2 메모리 특징
          Multi-THuMBS (2026)      — 샷 전환을 넘어 ID 유지 (코드 미공개)
```

**두 계열의 차이가 중요하다.** 월드 좌표 계열은 "카메라가 움직일 때
사람이 실제로 어디를 걸었는가"를 푼다. 다인물 계열은 "여러 사람을 동시에
놓치지 않고 각자의 ID를 유지하는가"를 푼다. 우리 데이터셋은 COLMAP으로
캘리브레이션된 고정 멀티캠이라 카메라를 이미 알고 있으므로, 후자가
직접적으로 필요한 계열이다.

# 3장. 대안 기법의 장단점

SMPL 계열만이 답은 아니다. 인체를 다루는 다른 표현들과 비교한다.

## 3.1 2D 키포인트

**OpenPose, ViTPose, RTMPose, [Sapiens](https://arxiv.org/abs/2408.12569)**

화면 위 관절 좌표 (x, y)만 낸다. Sapiens(Meta, ECCV 2024)는 인체 이미지
3억 장으로 사전학습한 ViT 기반 파운데이션 모델로, 2D 자세·부위 분할·
깊이·표면 법선 네 과제를 다룬다. 1K 고해상도 추론을 기본 지원하며
파라미터를 3억에서 20억까지 키울수록 성능이 오른다고 보고한다.

| 장점 | 단점 |
|---|---|
| 빠르고 성숙하다 | **3D 정보가 없다** |
| 학습 데이터가 풍부하다 | 깊이 모호성 — 팔을 앞으로 뻗은 것과 위로 든 것이 비슷해 보인다 |
| 어노테이션 비용이 낮다 | 카메라가 바뀌면 좌표의 의미가 바뀐다 |
| 여러 3D 방법의 입력으로 쓰인다 | 체형 정보가 없다 |

**VTG 관점**: 손이 물건에 닿았는지 같은 판단에 깊이가 필요한데, 2D로는
가려짐과 접촉을 구분할 수 없다.

## 3.2 3D 스켈레톤

**VideoPose3D, MotionBERT** 등. 2D 키포인트를 3D로 들어올린다(lifting).

| 장점 | 단점 |
|---|---|
| 3D 관절 위치를 얻는다 | **표면이 없다** — 접촉·부피·충돌을 다룰 수 없다 |
| 파이프라인이 가볍다 | 체형(β)이 없다 → 사람마다 뼈 길이가 다른 것을 표현 못 한다 |
| 학습이 쉽다 | 2D 검출 오류가 그대로 전파된다 |

**본 프로젝트 데이터셋의 기존 GT가 정확히 이 형태다.** `3DPose.txt` 는
관절 17개의 3D 좌표이고 메쉬는 없다. 우리가 SMPL 계열 레이어를
추가하려는 이유가 여기 있다.

## 3.3 비파라메트릭 / 암시적 메쉬

**PIFu, PIFuHD, [ICON](https://icon.is.tue.mpg.de/), [ECON](https://econ.is.tue.mpg.de/)**

점유 필드나 부호거리함수 같은 연속 함수로 표면을 표현한다.

| 장점 | 단점 |
|---|---|
| **옷·머리카락까지 복원**한다 | 애니메이션·편집이 어렵다 |
| 헐렁한 옷(드레스, 치마)도 표현 가능 | 파라미터가 없어 "이 사람"을 지정할 수 없다 |
| 시각적 충실도가 높다 | 무겁다 |

**핵심 트레이드오프**: 파라메트릭 방식은 해석 가능한 파라미터로 몸을
표현해 애니메이션에 적합하지만 표현력과 디테일이 제한된다. 암시적 방식은
복잡한 형상을 담아내지만 애니메이션과 편집을 어렵게 만든다.

또 하나 중요한 관찰이 있다. PIFu·PIFuHD는 **인체 구조 지식을 쓰지 않아**
새로운 자세에 일반화하지 못하고 팔다리가 끊어진 비인간적 형체를 만든다.
그래서 후속인 ICON과 ECON은 **SMPL-(X) 사전분포를 다시 끌어들여**
각각 자세 강건성과 의복 위상 유연성을 개선했다.

> 즉 이 계열조차 SMPL을 버리지 않았다. 1장 ①에서 말한
> "인체 사전지식이 모델 안에 박혀 있다"는 성질이 그만큼 값지다는 뜻이다.

**VTG 관점**: 우리는 옷 주름이 아니라 **동작**이 필요하다. 이 계열은
과잉이면서 동시에 부족하다.

## 3.4 3D 가우시안 / NeRF 아바타

**HumanNeRF, GART, 3DGS 기반 아바타**

| 장점 | 단점 |
|---|---|
| 사진처럼 사실적인 렌더링 | **한 사람에 대해 최적화**해야 한다 |
| 자유 시점 합성 | 새로운 사람에게 일반화되지 않는다 |
| | 동작 분석용 의미 정보가 없다 |

**VTG 관점**: 목적이 다르다. 렌더링용이지 이해용이 아니다.

## 3.5 정리 — 무엇을 얻고 무엇을 잃는가

| 표현 | 3D | 표면 | 체형 | 동작 의미 | 다인물 ID | 비용 |
|---|---|---|---|---|---|---|
| 2D 키포인트 | ✗ | ✗ | ✗ | 부분 | 별도 | 낮음 |
| 3D 스켈레톤 | ✓ | ✗ | ✗ | ✓ | 별도 | 낮음 |
| **SMPL 계열** | ✓ | ✓ | ✓ | **✓** | **모델에 따라 내장** | 중간 |
| 암시적 메쉬 | ✓ | ✓✓ | ✗ | ✗ | ✗ | 높음 |
| 3DGS 아바타 | ✓ | ✓✓ | ✗ | ✗ | ✗ | 매우 높음 |

**SMPL 계열이 유일하게 다섯 축을 모두 갖는다.** 최고는 아니지만
빠짐이 없다. 우리가 필요한 것 — 3D 동작, 사람별 구분, 시간에 걸친 추적,
그리고 그것을 자연어 질의와 연결할 해석 가능한 파라미터 — 이 전부
한 표현 안에 들어 있는 유일한 선택지다.
