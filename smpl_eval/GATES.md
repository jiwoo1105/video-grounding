```

```

### CoMotion 출력 구조 (실측 확정)

```
id        (N,)     int64    트랙 ID (1-base)
pose      (N, 72)  float32  SMPL θ, axis-angle 24관절
trans     (N, 3)   float32  루트 위치
betas     (N, 10)  float32  체형
frame_idx (N,)     int64    프레임 (0-base)
<name>.txt         MOT 포맷 (frame 1-base, id, x, y, w, h, conf, ...)
```
계획서에서 추정했던 키 이름 5개가 **전부 실제와 일치**했다.

관절 3D 는 CoMotion 내장 `SMPLKinematics(betas, pose, trans, "joints")` 로 얻는다
(smplx 별도 설치 불필요). 2D 투영은 `get_default_K` 와 동일하게
`K = [[2·max(W,H), 0, W/2], [0, 2·max(W,H), H/2]]`.

anny 패키지가 COCO 키포인트 회귀기를 내장하고 있어(`anny/data/keypoints/coco.pth`,
가중치 23×19158) 메쉬 정점에서 COCO-17+발6 을 직접 뽑을 수 있다.
**우리 GT 가 바로 그 COCO-17 이므로** 리토폴로지·SMPL 피팅 없이 직결된다.

실측 검증 (Data4): 허벅지 0.366m, 정강이 0.352m, 상완 0.243m, 전완 0.206m,
허벅지/상완 = 1.51 (실제 인체 약 1.5). 미터 스케일도 타당하다.

## 실행 중 잡은 평가 편향 2건

### ① bbox 생성 방식 불일치 (치명적)

증상: Data3 에서 CoMotion 이 트랙 2개를 완벽 유지(스왑 0, 인원수 MAE 0.00)
했는데 IDF1 이 **0.078** 로 나왔다.

원인: 예측-GT 매칭이 bbox IoU 인데 생성 방식이 달랐다.

| | bbox 출처 | 크기 (Data3 프레임100) | GT 와의 IoU |
|---|---|---|---|
| GT | 투영된 관절에서 유도 | 198×547 | — |
| Multi-HMR 2 | 투영된 관절에서 유도 | 208×597 | **0.843** |
| CoMotion | 모델의 MOT 검출 박스 | 300×749 | **0.482** |

CoMotion 의 MOT bbox 는 여백을 준 검출 박스라 각 변이 1.28~1.68배 크다.
IoU 가 임계값 0.5 **바로 아래**에 걸려 매칭이 전부 실패했다.
추적 품질이 아니라 **bbox 관례 차이**로 점수가 갈린 것이다.

수정 후 IDF1 변화: Data3 0.078→**1.000**, Data4 0.237→**0.795**, Data1 0.543→**0.666**

### ② 지터를 3D 전체로 재면 깊이 노이즈가 지배

CoMotion Data4 실측에서 전체 가속 628 중 z 성분이 618 (**98%**) 이었다.
댄서 루트 z 가 34.6~41.4m 로 요동하는데 제자리 춤이라 물리적으로 불가능하다.
단안 깊이 추정의 본질적 불안정성이다.

→ xy(화면평면)와 z(깊이)를 분리하고, **GT 를 기준선으로** 배율을 낸다.
GT 도 지터가 있으므로(춤은 원래 가속이 크다) 기준선 없이는 해석할 수 없다.

## ★ 핵심 발견 — 트랙 지속시간 ≠ 추적 정확도

Multi-HMR 2 의 Data4 트랙은 660/659/644 프레임으로 거의 완벽해 보였다.
그런데 GT 와 대응시켜 보니:

```
Multi-HMR 2 / Data4
  GT id1 → pred 0  (658)                 정상
  GT id2 → pred 2 (389) + pred 1 (267)   두 트랙이 서로 뒤바뀜
  GT id3 → pred 1 (374) + pred 2 (277)   같은 두 트랙, 반대로

CoMotion / Data4
  GT id1 → pred 1  (658)                 정상
  GT id2 → pred 2  (655)                 정상
  GT id3 → pred 26(432)+4(92)+19(48)     끊기지만 사람은 맞음
```

**두 모델의 실패 양상이 근본적으로 다르다.**

| | CoMotion | Multi-HMR 2 |
|---|---|---|
| 실패 방식 | **단편화** — 트랙이 끊겨 이어달리기 | **정체 혼동** — 트랙은 살아있는데 사람이 바뀜 |
| 육안 식별 | ID 숫자가 바뀌어 **보임** | ID 숫자가 그대로라 **안 보임** |
| 후처리 복구 | 가능 (트랙 재연결) | 어려움 (오류를 인지 못 함) |

정체 혼동이 더 위험하다. VTG 에서 "빨간 자켓 여자" 를 지정했는데 중간에
다른 사람으로 바뀌면 결과가 조용히 틀린다.

**GT 없이 트랙 길이만 보면 이 실패를 놓친다.** IDF1 이 정확히 이것을 잡는다.

## 원인 규명 — 왜 트랙이 끊기는가

추적은 **전적으로 모델 자체**다. 우리 코드는 모델 출력을 읽고 정규화만 한다.

| 후보 원인 | 판정 |
|---|---|
| CoMotion 의 장면전환 리셋 | ❌ **무죄.** 4개 영상 전부 컷 검출 0회 (단일 샷) |
| CoMotion 트랙 소멸 | 모델 설계. `overlap_thr=0.6`/`overlap_time_thr=20` 으로 붕괴 판정, 겹침 시 삭제 |
| CoMotion 단편화의 실제 위치 | **화면 경계** — 농구 조기종료 트랙 10개 중 6개가 경계<0.1 에서 죽음 |
| Multi-HMR 2 단편화의 실제 위치 | **중복 검출** — 조기종료 트랙의 종료 시점 평균 겹침 0.452 |

두 모델의 단편화 원인이 정반대다. CoMotion 은 사람이 화면 밖으로 나가서,
Multi-HMR 2 는 같은 사람을 두 번 잡아서 끊긴다.
