## 게이트 2 — GT 재투영 검증 ✅ PASS

`python3 -m smpl_eval.gt.reproject_check` → `smpl_eval/gate_out/data1_offset1/`

Data1 S03 Cam1 의 2D GT 를 영상에 겹쳐 그려 확인했다.

| 확인 항목 | 결과 |
|---|---|
| 초록 bbox 가 실제 선수를 감싸는가 | ✅ 13명 전원 정확히 일치 |
| 좌/우 골격선이 팔다리를 따라가는가 | ✅ COCO 연결 구조와 완전 일치 |
| 관절 17·18 이 발에 찍히는가 | ✅ 선수·심판 신발 위치에 정확히 표시 |
| 얼굴 관절 0~4 가 머리에 있는가 | ✅ |

**프레임 오프셋 = 1 확정.** 시각 확인에 더해 논리적 근거가 있다 —
GT 프레임 번호가 1~300 인데 영상은 0~299 프레임이므로, 오프셋 0 이면
존재하지 않는 300번 프레임이 필요해진다. 오프셋 1 만이 모순 없이 성립한다.

**관절 규약은 별도로 수치 확정했다** (스펙 §12.1). 뼈길이 강체성 비교에서
COCO 가 H36M 을 모든 데이터셋에서 이겼고(CV 0.046 vs 0.106 등),
인체 비율(허벅지/상완 ≈ 1.5)도 COCO 해석에서만 성립한다.

### Data2/3/4 의 프레임 오프셋 — 미검증

2D GT 가 없어 같은 방식으로 확인할 수 없다. 현재는 `detect_frame_offset`
의 추정값(GT 최소 프레임 번호)을 쓴다: Data2=0, Data3=2, Data4=2.
COLMAP 카메라로 3D GT 를 투영하면 검증 가능하나 본 스펙 범위 밖이다.
**파일럿에서 모델 예측과 GT 의 시간 상관을 보면 간접 검증할 수 있다** —
오프셋이 틀리면 PA-MPJPE 가 프레임 이동에 따라 체계적으로 변한다.

## 게이트 5 — 합성 ID 스왑 검출 ✅ PASS

`.venv-smpl/bin/python -m pytest smpl_eval/tests/test_identity.py -v`

정답을 아는 합성 트랙에 인위적으로 ID 스왑을 넣고 지표가 잡아내는지 확인.

| 케이스 | IDF1 | MOTA | ID-switch |
|---|---|---|---|
| 완벽 일치 | 1.000 | 1.000 | 0 |
| f=25 에서 ID 스왑 | **0.667** | 0.987 | **2** |
| 트랙 1개 누락 | 0.800 | **0.667** | 0 |

**부수 확인**: ID 스왑 시 MOTA 는 0.987 로 거의 반응하지 않고 IDF1 만
0.667 로 떨어진다. 검출은 다 맞고 ID 만 틀렸기 때문이다.
→ 본 평가의 축 ②(ID 유지)에는 **IDF1 이 정답 지표**임이 실증됐다.
MOTA 만 봤다면 ID 스왑을 놓쳤을 것이다.
